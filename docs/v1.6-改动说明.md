# 进京证助手 v1.1 → v1.6 · 改动说明

交付时间：2026-11-16　|　基于 GitHub `zhbin426/jjz-assist` main（commit `93acbb8`）

---

## 一、根因：三行字消失和百分比变小是同一个 bug

`PassWidgetProvider.kt` 里下发盒子高度时做了**双重单位换算**：

```kotlin
fun dp(v: Float) = (v * density).toInt()                       // 已经换成 px
views.setViewLayoutHeight(R.id.pct, dp(pH).toFloat(), TypedValue.COMPLEX_UNIT_DIP)  // 又当 dp 用
```

`dp()` 已经把 dp 乘过一次 density，`COMPLEX_UNIT_DIP` 又让系统再乘一次。小米 17 Ultra 的 density≈3.5，四个文字盒子的高度因此被撑到**3.5 倍**（例如 31dp 的百分比盒变成 108dp）。

而 `setViewPadding` 传的是正确的 px 值。盒子虚高之后：

- **剩余天数 / 到期日 / 年度余次**：这三行位置靠下，paddingTop 已经接近甚至超过盒子自身高度，内容区高度变成负数，文字被整行裁掉 → 全部消失。
- **百分比**：位置靠上，paddingTop 还留了点内容区，所以字还在，但 autoSize 在这个畸形盒子里按剩余高度收缩 → 字号明显变小。

一个换算错误，同时解释了你报的两个现象。标题「进京证」没设 `setViewLayoutHeight`（wrap_content），所以它一直正常显示——这也反过来印证了问题就在这一处。

**修复**：`setViewLayoutHeight` 直接传 dp 浮点值 + `COMPLEX_UNIT_DIP`，不再预乘 density；`setViewPadding` 继续传 px。代码里已加注释标为铁律。

## 二、剩余天数：跟水面下降，贴近到期日就钉住

原公式 `daysCap = dateTop - dH`，天数盒下沿会**正好贴住**到期日盒上沿（缝为 0），视觉上就是重合。

改为：

```kotlin
val daysCap   = dateTop - dH - gap        // 硬上限：到期日上沿再留一个缝，到此钉死
val daysFloor = topLimit + pH + gap       // 硬下限：永远压不到百分比盒
val daysTop   = minOf(maxOf(surface + h*0.025, daysFloor), maxOf(daysCap, topLimit))
                  .coerceAtLeast(topLimit)

val pctAnchor = if (filled) daysTop else dateTop
val pctMax    = (pctAnchor - gap - pH).coerceAtLeast(topLimit)
val pctTop    = (surface - pH*1.12).coerceIn(topLimit, pctMax)
```

关键点：百分比的上限改为**由天数实际位置反推**（原来是从 `bottomLimit` 静态推的）。这样天数被钉住之后，百分比继续上浮时会自动让位，两者不会撞在一起；天数不显示（已过期/未设置）时，百分比可以让到到期日上方，位置更自然。

**验证**：h = 85–260dp、pct = 0–100%（步进 2%）全档位扫描，重叠 0、越界 0、无解档 0。以 h=130dp 为例：pct≥40% 时天数跟着水面走，pct≤20% 时钉死在 72.0dp（= daysCap），到期日固定在 90.6dp，中间始终留 gap。

拆开原 debug 包，45MB 的构成是这样的：

| 组成 | 大小 | 占比 | 说明 |
|---|---|---|---|

1. **ABI 拆包**（`splits.abi`）：按架构分别出包，每台机器只装自己那份。省 27MB。
2. **R8 混淆 + 资源压缩**（release 构建）：dex 5.87MB → **0.80MB**，省 5MB。
3. **packaging excludes**：剔掉 META-INF 里的许可证和依赖清单冗余。

| 包 | 大小 | 适用 |
|---|---|---|
| `进京证助手-v1.1-arm64.apk` | **12.36MB** | 小米 17 Ultra 及所有现代机型（装这个） |

还能再瘦的路，但**不建议**：换成非捆绑版依赖 `com.google.android.gms:play-services-mlkit-text-recognition-chinese`，APK 能降到约 5MB，模型改由 Google Play 服务在运行时下发。问题是国行小米没有 GMS，OCR 会直接失效——所以这条路对你的机器不通。剩下 9.54MB 的 arm64 原生库是 ML Kit 自带的推理引擎，除非换成 PaddleOCR/RapidOCR 之类的轻量方案，否则降不下去。

# v1.2 追加（2026-11-16 下午）

## 一、先回答：剩 3.6 天格子里的粉红线和浅红底是什么

都在设计内，不是 bug：

- **粉红线 = 水面亮线**。液面顶部那条 blend 60% 白的高光线，用来标出"水位"。
- **浅红底 = 液面本体**。水面以下的渐变液体，漏斗语义就靠它表达剩余量。

为什么它们会贴在"剩 3.6 天"下面：3.6 天 = 30% 档，水面在卡片 70% 高度处，而那个位置正好是底部文字带（到期日/年度余所在区域）。天数行在低百分比时按你上一轮的要求**钉住**在到期日上方，于是水面线就落在了天数行和到期日行之间，液面则铺在到期日/年度余两行背后——看起来像"多出来的下划线和底色"。

v1.2 的处理：**水面线落进底部文字带（>62% 高度）时按距离线性淡出**，到 82% 高度完全消失；液面本体保留（它是剩余量的表达，去掉漏斗就没了意义）。如果你连液面也不想压在小字背后，说一声，我把液面在文字带里也压一档透明度。

# v1.5 真机文字消失根因 + 主界面按钮收排（2026-11-16 傍晚）

## 一、为什么真机上四行字全没显示（只剩"进京证"标题）

真机截图确认：波浪液面、半透明水上区都正常，唯独百分比/天数/到期日/年度余四行整行消失，标题幸存。

根因在 `RemoteViews.setViewLayoutHeight(viewId, value, unit)` 的**单位参数在 MIUI 启动器上不生效**：传 `31f + COMPLEX_UNIT_DIP`，原生安卓会换算成 ~108px，MIUI 直接把 31 当 px 用。31px 高的盒子装不下 autoSize 的最小字号（12sp ≈ 42px），文字被整行裁掉。标题没调 setViewLayoutHeight（wrap_content），所以只有它活下来。这也解释了之前几版真机表现的差异。

修复：盒子高度统一传**已换算的 px 值 + COMPLEX_UNIT_PX**。px 值在两种实现下语义一致，原生和 MIUI 都正确。排版公式本身没动，预览模拟不受影响。

# v1.6 组件改单 ImageView 整图渲染（2026-11-16 晚）

## 症状对照

真机：**App 内预览有全部文字，桌面组件只有"进京证"标题**。预览走 Canvas 画字、组件走 RemoteViews 原生 TextView——同一份数据两条管线，差异只能出在 RemoteViews 层。v1.5 已把盒子高度改成 px+UNIT_PX 仍无效，说明 MIUI 启动器对 RemoteViews 的文本/布局 API 兼容性问题不止单位一处，继续逐个猜 API 代价太高。

## 方案

组件布局 `widget_pass.xml` 砍到只剩一张 ImageView；整张画面（圆角卡片、半透明水上区、波浪液面、五行文字含阴影）由 `WidgetRenderer.render(context, wPx, hPx)` 按**组件实际像素 1:1** 渲染成位图下发。

- 位图尺寸 = 组件尺寸，fitXY 不产生拉伸——当年"整张位图画字"被否决的原因是固定尺寸位图被拉伸压扁糊字，这个前提现在不成立；
- 文字是 Canvas 按 px 画的，密度自适应，清晰度与预览完全一致；
- 组件与预览从此**必然一致**：预览看到什么，桌面就是什么；
- 点击打开 App、到期闹钟、开机重刷等逻辑不变；onAppWidgetOptionsChanged 会在组件尺寸变化时重渲染。

代价：文字不再是原生 TextView（无障碍朗读拿不到组件文本），对这个纯自用工具可接受。

versionCode 7 / versionName 1.6，签名不变，覆盖升级。
